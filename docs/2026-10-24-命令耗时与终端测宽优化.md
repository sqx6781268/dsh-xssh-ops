# 命令台账耗时时间线与终端测宽优化（2026-10-24）

> 目的：记录本轮两处改动的**语义约定**与**依赖的第三方私有契约**，让后来者能判断「改了会不会坏」以及「坏了怎么退」。
> 适用对象：维护本插件的开发者、AI 智能体。
> 当前状态：2026-10-24，基线 main `ffe1f03`（0.1.7）；本地已实现并通过测试、构建、lint、i18n 检查；未提交、未发布。
> 维护方式：改到台账时间线字段、或升级 `@xterm/xterm` 版本时，先按本文第 2 节的契约清单逐条复核，再更新对应测试（`test/command-ledger.mjs`、`test/dom-width-cache.mjs`、`test/wiring-audit.mjs`）。

## 1. 命令台账：输出时间线与耗时

### 1.1 为什么加

原台账只记 `issuedAt`（发出）与 `closedAt`（闭口），回答不了「这条命令是慢在**响应**还是慢在**执行**，还是慢在我等它安静」。闭口本身还含一段**空闲等待**（默认 1500 ms），把 `closedAt - issuedAt` 当成执行时间是错的。

### 1.2 字段语义（三段时间，互不替代）

| 字段 | 含义 | 由谁写 | 是否含空闲闭口等待 |
| --- | --- | --- | --- |
| `issuedAt` | 命令发出时刻 | `open()` | — |
| `firstOutputAt` | **首字节**输出到达时刻（只在第一次写） | `noteOutput()` | 否 |
| `lastOutputAt` | **最后一块**输出到达时刻（每次推进） | `noteOutput()` | 否 |
| `closedAt` | 台账闭口时刻 | `closeRecord()` / `markOutcome()` | **是**（含判据②的静默等待） |
| `firstOutputMs` | `firstOutputAt - issuedAt`，纯响应延迟 | `closeRecord()` 派生 | 否 |
| `durationMs` | `lastOutputAt - issuedAt`，纯执行时间 | `closeRecord()` 派生 | 否 |

约定：

- **没有任何输出时不编造 0**。`firstOutputAt`/`lastOutputAt` 保持 `null`，`firstOutputMs`/`durationMs` 保持**不存在**（不是 0）。这样「这条命令没有任何输出」和「耗时 0ms」在数据上可区分，客户端也就不会显示耗时（`timingLabel()` 返回 `null`）。
- **派生只在 `closeRecord()` 一处做**。`closeFromShellIntegration` / `closeFromExec` / `closeIfIdle` / `closeAll` / 下一条命令的 `next-command` 全部经它收口，因此不存在"某条闭口路径没有耗时"的分叉。发送失败走 `markOutcome()`，那时必然没有输出，不派生。
- **毫秒值从 ISO 字符串反解**（`Date.parse`），因为内存记录与 JSONL 落盘用的是同一份 ISO 文本；`issuedAt` 不可解析时整个派生跳过，不产出 `NaN`。

### 1.3 客户端展示

`src/client/CommandLedger.jsx` 的 `timingLabel(record)` 把两个毫秒值转成一行小字：

- `↵120ms` = 发出→首字节（响应延迟），`Σ900ms` = 发出→最后一块（执行时间）；
- 两者相等时只显示一个（避免重复）；
- `title` 里给出中文全称与台账闭口时刻（`台账闭口 HH:MM:SS`），语义不会被误读；
- **每条记录只计算一次**（在 `map` 回调里提成局部变量）。此前条件、`title`、正文各调一次，既重复做 `t()` 与本地时间格式化，又可能跨秒取到不同值。

### 1.4 wire 契约

`firstOutputAt` / `lastOutputAt` / `closedAt` / `firstOutputMs` / `durationMs` 同步进三处，缺一处客户端就拿不到数据：`src/schemas.js`（`commandRecordSchema`）、`src/typert.js`（`CommandRecord` 声明）、`src/i18n/messages.en.js`（新增文案）。`test/typert-sync.mjs` 守这三处一致。

## 2. 终端 DOM 渲染器：改用 canvas 量字符宽度

### 2.1 为什么

`@xterm/xterm` 的 DOM 渲染器在 `WidthCache._measure()` 里用 `el.offsetWidth` 量字符宽度，**每次缓存未命中都触发一次强制同步布局**；`handleCharSizeChanged()` 又会清空整个宽度缓存，于是改一次字号要把用到的字符全部重量一遍。

实测（DSH 桌面端，266 个样式表 / 13023 条 CSS 规则 / 12821 个节点）：单次强制布局 ≈ 95.7 ms，改一次字号 4.1–11.3 秒；换成 canvas 测量后同一操作 **8 ms**，校准偏差 7.81px vs 7.80px。

### 2.2 依赖的第三方私有契约（升级 xterm 前必须复核）

补丁文件：`src/client/dom-width-cache.js`，挂载点：`src/client/SshPanel.jsx`（`term.open()` 之后，以及字号变更之后各一次）。

| 依赖项 | 本版（5.5.0）事实 | 判据 |
| --- | --- | --- |
| 取渲染器 | `term._core._renderService._renderer` 是 `MutableDisposable`，渲染器在 `.value`（少数版本直接是渲染器本体） | 两种形态都试，取不到就返回 `false` |
| 只认 DOM 渲染器 | `DomRenderer._widthCache` | 没有该字段（canvas/webgl 渲染器）直接放弃 |
| 测量函数 | `WidthCache._measure(text, variant)` 是**原型方法**，实例赋值可覆盖 | 赋值后 `get()` 会调到新实现 |
| `variant` 位约定 | `FontVariant`：REGULAR=0、BOLD=1、ITALIC=2、BOLD_ITALIC=3；`get()` 里 `bold && (variant \|= 1)`、`italic && (variant \|= 2)` | 补丁按同一位约定还原 `font` 简写：`variant & 1` → `_weightBold`，`variant & 2` → `italic` |
| 字体字段 | `_font`（family）、`_fontSize`、`_weight`、`_weightBold` 全是**私有字段名**，但产物未做属性混淆 | 直接读 live 值，因此字号/字体变化后自动跟随，无需重挂 |
| 测量元素 | `_measureElements` 是 4 个 span（regular/bold/italic/boldItalic），顺序即 `variant` | 少于 4 个即视为结构变更，放弃 |
| 缓存填充时机 | `_measure` 只在缓存未命中时被调用，命中走 `_flat`/`_holey` | 补丁只需替换测量，不必碰缓存结构 |

### 2.3 安全阀

1. **双路校准**：拿 5 个代表字符（`M` `i` `W` `0` 与一个宽字符，宽字符用码点构造以免被 i18n 检查器当成文案）分别用 `offsetWidth` 与 `measureText` 量，差异 > 0.5px 就**放弃补丁**并保留 xterm 原行为。这条守的是"canvas 与 DOM 排版不一致"（字体未就绪、kerning、可变字体特性），此时宁可慢也不要用错宽度。
2. **全程静默退化**：结构不符、拿不到 2d 上下文、`_measureElements` 数量不对，一律 `return false`，调用点再包一层 `try/catch`——补丁失败只是没有加速。
3. **幂等**：实例上留 `__xsshOpsCanvasMeasure` 标记，重复挂载直接返回 `true`；原始实现存在 `__xsshOpsOriginalMeasure`，`unpatchDomRendererWidthCache()` 可完整回滚。
4. **诊断输出**：`localStorage['xssh-ops:debug']='1'` 时打印中文日志（已启用/已跳过，都带校准偏差值）。

### 2.4 测试

`test/dom-width-cache.mjs` 用形状与 xterm 一致的替身锁住最容易错、且在源码 review 里看不出来的两条：① `variant` 位约定（写反不会报错，只会让粗体用常规字重）；② 校准失败必须放弃补丁、保留原实现。另外覆盖结构容错、`_renderer` 无 `.value` 包装、幂等与回滚。

`test/wiring-audit.mjs` 已把本模块登记进能力清单，并断言客户端产物里存在 `__xsshOpsCanvasMeasure`——防止「只被 import、没被调用」被 esbuild 摇掉后，界面上只表现为"没变快"。

## 3. 本轮不改动的范围

- 不替换渲染器（不引入 webgl addon）、不改 xterm 版本、不改 `letterSpacing`/`lineHeight` 语义。
- 不改台账闭口判据（OSC 133 D → 空闲静默 → 下一条命令）的优先级与顺序。
- 不改 `closedAt` 的既有含义（仍含空闲闭口等待）；耗时一律从新字段读。
- 不动 `repo-github/`、`release-v*`、`*.log`、`*.png`。
