# 经 SOCKS5 代理连接服务器 —— 使用说明

> 目的：说明如何让 dsh-xssh-ops 先连 SOCKS5 代理、再由代理连目标服务器，并讲清**两种代理填法完全不同**这一最容易踩的坑。
> 适用对象：使用本插件的运维人员（面向人类，步骤可照做）。
> 当前状态：本地补丁（尚未合并上游）。基线：v0.3.20。
> 维护方式：界面字段名以实际面板为准；若与本文不符，先核对再改文档。

---

## 一、这个功能解决什么问题

有些目标服务器**不能直连**，只能经一台 SOCKS5 代理到达。插件此前的两种"上游"能力都不是这个：

| 你可能会想用的 | 实际是什么 | 能不能代替代理 |
| --- | --- | --- |
| 跳板机（ProxyJump） | 上游必须是**能登录的 SSH 服务器**（要账号、要认证、要过主机指纹校验） | ❌ 代理通常不需要账号，语义不同 |
| 动态 SOCKS5 隧道（`ssh -D`） | 插件**对外提供**一个代理出口 | ❌ 方向相反，那是"提供代理"不是"使用代理" |

本功能新增的是**使用**代理：插件的 SSH 拨号先连代理，由代理去连目标。

---

## 二、前置条件

- 你已经知道代理的 **地址、端口**（例如 `192.168.10.4:1080`）；
- 若代理要求认证，你还需要 **用户名 / 密码**；
- 代理类型为 **SOCKS5**（本版不支持 HTTP/HTTPS CONNECT 代理）。

> 代理密码保存在 DSH 本机凭据库（由 DSH 凭据服务托管，不随资源记录持久化），不落资源记录、不进浏览器存储、不进 Agent 上下文，也不经过 `profileSave` 请求体；前端拿到保存接口返回的 `credentialRefs.proxyPassword` 后直接写入凭据库，连接时由主机解析。

---

## 三、配置步骤

1. 打开 **设置 → SSH 资源**，新建或编辑一台服务器。
2. 在「**代理（SOCKS5）**」区块填写：
   - **主机**：代理地址（如 `192.168.10.4`）；
   - **端口**：代理端口（如 `1080`）；
   - **用户名 / 密码**：仅当代理要求认证时填写；**免认证代理请留空**。
3. 服务器自身的 **主机 / 端口**按第四节选择填法（这一步最容易错）。
4. 保存后连接。资源卡片与连接对话框的「跳板机（ProxyJump）」区块行为不变，代理与跳板机可以同时使用（此时**第 1 跳**经代理拨号）。

> 界面上的字段名与所在区块以实际面板为准；本节描述的是配置语义。

---

## 四、关键：两种代理，两种填法（务必对照）

同样叫"SOCKS5 代理"，行为可能完全不同。**填错不会报错，只会静默失败**（收到"连接成功"却什么都收不到）。

### 4.1 标准 SOCKS5 代理 —— 填真实服务器地址

代理按你请求的目标地址去连，域名由代理侧解析。

| 字段 | 填什么 |
| --- | --- |
| 代理主机 / 端口 | `192.168.10.4` / `1080` |
| 服务器 **主机** | **真实目标**，如 `192.168.10.11` |
| 服务器 **端口** | 真实端口，如 `22` |

**实测**：`CONNECT 192.168.10.11:22` → 收到 banner `SSH-2.0-OpenSSH_7.4`，与直连该目标的 banner **逐字节一致**。补丁实现的 `socks5Connect` 拨号约 54ms 拿到 banner；进一步把该隧道作为 ssh2 的 `config.sock` 做**完整公钥握手 + `exec whoami`** 成功（握手约 301ms，返回 `root`，内核 `3.10.0-1160.71.1.el7.x86_64`，即 CentOS 7.9），证明不仅隧道通、整条 SSH 链路也通。

### 4.2 端口转发式代理 —— 必须填 `127.0.0.1`

这类代理**忽略你请求的目标地址**，只认它自己本机上的端口。你请求什么主机它都回"成功"，然后立刻关闭连接。

| 字段 | 填什么 |
| --- | --- |
| 代理主机 / 端口 | `192.168.10.4` / `18092` |
| 服务器 **主机** | **`127.0.0.1`** |
| 服务器 **端口** | **代理机侧的端口**，如 `3306` |

**实测**：

- `CONNECT 127.0.0.1:3306` → 收到 MySQL `5.5.50` 握手 ✅
- `CONNECT 192.168.10.11:22`（或任何其他主机）→ 回 `rep=0`「成功」但 **0 字节静默关闭** ❌

**怎么判断自己遇到的是哪一种**：如果"连接成功"却立刻断开、没有任何 banner，几乎可以断定是转发型代理被当成了标准代理用——把服务器主机改成 `127.0.0.1`、端口改成代理机侧的端口再试。

### 4.3 速查对照表

| | 标准 SOCKS5（如 `:1080`） | 端口转发式（如 `:18092`） |
| --- | --- | --- |
| 服务器主机填 | 真实目标地址 | `127.0.0.1` |
| 服务器端口填 | 真实端口 | 代理机侧端口 |
| 域名能否直接用 | 能（代理侧解析） | 不适用 |
| 填错的症状 | 代理拒绝连接（有明确 rep 码） | **"成功"后 0 字节静默关闭** |

## 五、关于认证的两个要点

1. **免认证代理：用户名/密码一律留空。** 部分代理只要客户端"声明支持账号密码"就会强制要求认证——本补丁按"**有凭据才声明认证方法**"设计，所以留空时免认证连接不会被误伤。反过来，若代理本可免认证而你把密码填了，可能会因为密码不对而失败：**能留空就留空**。
2. **认证失败与代理不可达是两类错误**，插件会给出不同提示：
   - 代理不可达 → 检查地址/端口/网络（**会重试**）；
   - 代理无响应 / 连上后 0 字节静默关闭 → 多为"转发型代理被当成标准代理用"，见 4.2（**会重试**）；
   - 代理要求认证但没配 → 补用户名/密码（**不重试**）；
   - 代理认证失败 → 核对用户名/密码（**不重试**，避免白等退避）；
   - 代理拒绝连接目标 → 看返回的 rep 码含义（规则不允许 / 连接被拒绝等）（**不重试**）。

   > 归类原则：网络/代理侧的**暂时**状况会按既有退避重试；**确定性**结论（认证失败、规则拒绝）立即报错，不做无意义重试。

## 六、常见问题（FAQ）

**Q：配了代理，但日志/行为看起来像直连？**
本补丁的设计覆盖全部三处拨号路径（主连接、横幅修复路径、跳板链第 1 跳），正常情况下不应绕过。若仍怀疑，先确认资源确实保存了代理配置，再看是否命中"横幅修复"分支。

**Q：能用域名吗？**
能。域名按 SOCKS5 的 `atyp=3` **原样透传给代理**，由代理侧解析——所以内网域名在本地解析不了也没关系。

**Q：代理和跳板机能一起用吗？**
能。此时**第 1 跳经代理**拨号，其余跳照旧走 SSH 转发。

**Q：主机指纹（TOFU）会有影响吗？**
指纹仍按目标 `host:port` 校验，与是否走代理无关。**注意**：用转发型代理（填 `127.0.0.1`）时，多台不同资源都会表现为 `127.0.0.1:22`，指纹可能互相覆盖——这是该模式的固有特性，建议这类场景给资源起清晰的名字并留意指纹提示。

**Q：不配代理的连接会受影响吗？**
不会。不填代理时行为与改动前完全一致。

## 七、本地自测（不依赖内网）

若本机运行了 Clash/Mihomo 一类工具，其 `127.0.0.1:7890` mixed 端口同时支持 HTTP 与 SOCKS5 且免认证，可作为标准 SOCKS5 代理的本地自测通路（填法同 4.1）。
